# Sports-App
## Intro to SWE Sports App
### Course Specifications:
- Implements **user authentication** with at least two distinct user types (e.g., **administrator**
and **member**)
  - admin will be able to manage users (add or remove of users)
  - member will be able to use the app
- Implements a dynamic database of user and item data
    - Store users
    - Authicate
    - API sports (api sports io)
      - Limit 100 request per day
- Implements one or more “operations” involving some form of frontend-backend-database
communication
  - User sign in (SSO?)
  - Pulling the sports data from user request and displaying on the frontend
  - Pull all at once at the start -> store in the DB
  - Refresh every 24hrs  
### Course Expectations:
- Databases can use any existing dataset or have dummy data. Databases using datasets
should have at least 100 items. There can be exceptions based on the specific project.
  - From the API
- New User creation/registration should be available
  - User sign on
- UI design should contain elements commonly found or expected such as a user profile,
login, and logout.
 - Basic UI
 - Pull stats
 - Logos come from API
- Consideration for design aesthetics
- System should be dynamic and responsive
  - Maybe make a mobile and computer responsive
